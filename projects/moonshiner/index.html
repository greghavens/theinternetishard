Moonshiner

For people building instruction-following, coding, and tool-use datasets who need more than a collection of final answers.

A PROJECT BY GREG HAVENS

THE PROJECT, IN PRACTICE

What you can do with it.

01

Start with seeds

Author tasks and choose the harnesses and models that generate and judge them.

02

Keep the development loop

Capture model trajectories, including tool interactions, corrections, and the steps that led to the result.

03

Judge before publishing

Independent review accepts or rejects traces. Rejected work can be retried before it enters the prepared dataset.

04

Keep the queues moving

Seed authoring, tracing, judging, formatting, privacy checks, local storage, and Hugging Face publication run as independent queues.

FROM IDEA TO USE

How it works.

  1. 01

    Configure the roles

    Choose author and judge models, providers, project storage, and publication preferences.

  2. 02

    Generate and review

    Run enabled queues and inspect accepted traces, rejections, retries, and throughput.

  3. 03

    Prepare and publish

    Format accepted trajectories for training and publish to your configured Hugging Face dataset.

From installation to the first run
python3 -m pip install moonshiner
moonshiner

# Inspect the active project
moonshiner status
moonshiner doctor

The first run opens setup. Model providers may require credentials and incur their own usage costs.

TAKE IT FOR A SPIN

Start here.

Install Moonshiner, run the setup assistant, and select your author and judge roles. Start with a small project and inspect the accepted traces before scaling up.

STATUS & REQUIREMENTS

Pi and Codex can author traces and seeds. Claude Code is supported as a judge. Provider access, credentials, and upstream terms depend on your selected configuration.
