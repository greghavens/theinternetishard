THE PROJECT, IN PRACTICE

What you can do with it.

01

A project that follows the model

One workspace represents one model lifecycle. Research, immutable dataset versions, recipes, runs, and exports stay connected through model-version lineage.

02

Recipes you can inspect

Work with a typed graph or edit the recipe as JSON. Revisions, bounded iteration, conditions, and artifact ancestry preserve the structure of an experiment.

03

Humans and agents share the controls

The workbench and native MCP server use a shared authenticated operations service. External agents can work with the same project operations.

04

Know what training actually consumed

Dataset previews, consumption records, checkpoint evaluation, and functionality-family policies connect training runs to their data and evaluation results.

FROM IDEA TO USE

How it works.

  1. 01

    Bring your research

    Start a model project and organize source material, datasets, and the code it depends on.

  2. 02

    Build the recipe

    Choose training and evaluation components, configure resources, and retain a versioned recipe.

  3. 03

    Run, compare, export

    Inspect checkpoints and evaluation results, compare model versions, and prepare an export with its lineage intact.

runs            Checkpoints, metrics, artifacts
model versions  Comparisons and lineage
exports         Reviewed publication bundles
